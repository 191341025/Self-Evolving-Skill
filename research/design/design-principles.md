## 原则一：VPRM — 规则优先，LLM 兜底

**Verifiable Program Reasoning Module：能用规则判定的地方用规则，规则判定不了的地方才用 LLM。**

LLM 的价值在于语义理解和判断力，不在于执行确定性逻辑。把确定性逻辑交给 LLM 既浪费其能力，又降低准确性。

| 判定类型 | 执行者 | 示例 |
|---------|--------|------|
| 数学计算 | Python | 衰减公式、贝叶斯因子、阈值分类 |
| 格式解析/写入 | Python | decay 标签解析、entities 标签 |
| 配置查表 | Python | λ_base 按 type 查 LAMBDA_TABLE |
| 语义价值判断 | LLM | Gate 1 "这条知识值得存吗" |
| 矛盾检测 | LLM | Gate 2 "新知识和已有知识矛盾吗" |
| 冗余判断 | LLM | Gate 3 "语义重复吗" |

**应用方法**：设计新功能时，先问"这个判定能否用规则/公式/代码实现？"能 → 不给 LLM。

## 原则二：表达三层优先级

**公式 > 结构化自然语言 > 自然语言**

每一层都有成本（实现、维护、认知负担），只有收益大于成本时才上升。

| 层级 | 适用场景 | 判断标准 |
|------|---------|---------|
| 公式 | 数学模型能真正提高精确度、可测试性、可复现性 | 公式的价值是否不可替代？是 → 用 |
| 结构化 NL | 步骤式/表格式/条件分支式提示词 | 结构化是否比自由文本提高了 LLM 遵循率？是 → 用 |
| 自然语言 | 清晰、简洁的意图描述 | 默认起点，够用就不上升 |

**绝不为了公式而公式。** 如果公式没有实际价值（不比结构化 NL 更精确/更可靠），不用。

**应用方法**：从最轻的层开始评估——自然语言够不够？不够 → 结构化 NL。还不够 → 公式。

---

## 两条原则的关系

- **VPRM** 决定"谁来做"（规则 vs LLM）
- **三层优先级** 决定"怎么表达"（公式 vs 结构化 NL vs NL）

合在一起：**规则能做的交给规则，用最合适的精度层表达。**

---

## 补充原则：反馈的聚合性

**反馈的价值来自多次独立观察的跨会话聚合，而非单次观察的完整性。**

每一次会话是一个独立的"观察者"。不需要每个观察者都完整记录，稀疏但真实的自然反馈通过贝叶斯 α/β 模型聚合后，收敛到知识的真实质量。

- 不追求反馈的 100% 覆盖率
- 自然发生的反馈信号质量 > 强制产生的机械性反馈
- 架构保持模型无关：多 LLM 实例共享同一 knowledge base 时，α/β 自然聚合
